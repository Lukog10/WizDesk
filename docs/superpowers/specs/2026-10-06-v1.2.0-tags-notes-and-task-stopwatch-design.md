# WizDesk v1.2.0 Design Specification: Tags, Active Stopwatch Time Tracking, and Permanent Long Notes

## 1. Overview and Scope

This specification defines the complete architecture, data models, UI components, and state workflows for **WizDesk v1.2.0**.
WizDesk v1.2.0 delivers three interconnected pillars:

1. **Custom Tags & Versatile Icon Library**: User-defined tags featuring names, curated vector icons, and hex colors. Includes bottom add-bar redesign replacing the wide project combo box with compact project and tag icon-buttons, plus tag badges in task rows.
2. **Task Active Stopwatch & Elapsed Time Tracking**: Dynamic work duration measurement using an active stopwatch with start, pause, and stop controls. Replaces static creation-to-completion calendar ranges with accurate work duration, featuring crash and shutdown persistence across Windows reboots.
3. **Permanent Long-Form Notes Engine**: Transforms the single-line scratchpad notes into a structured, title-first knowledge base with Markdown support, tag/project linking, and direct Obsidian vault synchronization.

### 2.2 Database Schema Extensions (`wiz/storage/db.py`)
New tables define the Tag entity and its relationships with Tasks and Notes:

```sql
CREATE TABLE IF NOT EXISTS tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL,
    icon TEXT NOT NULL DEFAULT 'tag',
    color TEXT NOT NULL DEFAULT '#3B82F6',
    created_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS task_tags (
    task_id INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (task_id, tag_id)
);

CREATE TABLE IF NOT EXISTS note_tags (
    note_id INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
    tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (note_id, tag_id)
);

CREATE INDEX IF NOT EXISTS idx_task_tags_task_id ON task_tags(task_id);
CREATE INDEX IF NOT EXISTS idx_task_tags_tag_id ON task_tags(tag_id);
CREATE INDEX IF NOT EXISTS idx_note_tags_note_id ON note_tags(note_id);
CREATE INDEX IF NOT EXISTS idx_note_tags_tag_id ON note_tags(tag_id);
```

## 3. Pillar 2: Active Task Stopwatch and Duration Tracking

### 3.1 Time Tracking Engine Specification
Instead of computing static timestamp ranges from `created_at` to `completed_at`, WizDesk introduces an active stopwatch tracking engine:

1. **Fields on `tasks` and `subtasks`**:
   * `duration_seconds INTEGER DEFAULT 0`: Cumulative verified work seconds.
   * `timer_started_at TEXT DEFAULT NULL`: Active session start timestamp (ISO-8601). When `NULL`, timer is paused or stopped.
2. **Stopwatch States**:
   * **Not Started**: Task status is `not_started`. Stopwatch icon is neutral outline (`#71717A`). Display shows empty or `0m`.
   * **In Progress**: Task status is `in_progress`. Stopwatch icon glows with theme accent color (`#FF6B3D` / `#BA3F1A`). Live QTimer ticks every 1000ms updating displayed time: `MM:SS` (or `H:MM:SS` if over 1 hour).
   * **Paused**: Task status remains `in_progress` or user clicks pause. Running session delta is committed to `duration_seconds`, and `timer_started_at` is set to `NULL`. Display shows frozen cumulative duration.
   * **Completed**: Task marked `done`. Running delta is flushed into `duration_seconds`, `timer_started_at` set to `NULL`, `completed_at` set to current timestamp. Displays clean completed duration badge, e.g. `(24m)` or `(1h 15m)`.
3. **Shutdown and Crash Resilience**:
   * On application close or Windows shutdown signal (`closeEvent` / `aboutToQuit`), all active running tasks are identified:
     ```python
     delta = int((datetime.now() - task.timer_started_at).total_seconds())
     new_duration = task.duration_seconds + max(0, delta)
     db.update_task_stopwatch(task.id, duration_seconds=new_duration, timer_started_at=None)
     ```
   * On next app launch, task remains `in_progress` with its cumulative duration intact.

## 4. Pillar 3: Permanent Long-Form Notes Engine

### 4.1 Storage Model
The `notes` table is upgraded into a first-class knowledge entity:

```sql
ALTER TABLE notes ADD COLUMN title TEXT DEFAULT '';
ALTER TABLE notes ADD COLUMN updated_at TEXT DEFAULT '';
ALTER TABLE notes ADD COLUMN is_pinned INTEGER DEFAULT 0;
```

Full record representation:
```python
@dataclass
class NoteRecord:
    id: Optional[int]
    title: str
    content: str = ""
    project_tag: Optional[str] = None
    created_at: datetime = field(default_factory=datetime.now)
    updated_at: datetime = field(default_factory=datetime.now)
    is_completed: bool = False
    is_pinned: bool = False
    tags: List[TagRecord] = field(default_factory=list)
```

### 4.2 Workspace Notes Interface
The Notes section in the Workspace window (`wiz/ui/workspace_dialog.py` / `wiz/ui/popup_dialog.py`) is elevated to a dual-pane knowledge center:

1. **Note Cards / Master List (Left Pane / Top Tier)**:
   * **Quick Create Header**: Title input with placeholder `+ Note Title (Press Enter to create)` and Project/Tag dropdowns.
   * **Cards List**: Displays note cards featuring Title (bold), project badge, tag pills, last modified date, and 2-line snippet preview of Markdown content.
   * Right-click options: Pin note, Rename, Assign Project/Tags, Delete.
2. **Note Detail Editor (Right Pane / Detail View)**:
   * Clean, distraction-free document editor.
   * Header: Editable Title, Project selector, Tag selector, Created/Updated timestamps.
   * Body: Multi-line rich text / Markdown editor with syntax highlighting, word wrap, and line spacing.
   * Auto-save on typing (debounced 1000ms) and on focus lost.
3. **Obsidian Vault Sync Integration**:
   * When Obsidian vault path is configured in Settings, each permanent note automatically writes/syncs to `<Vault>/WizNotes/<Title>.md`.
   * Includes frontmatter YAML with tags, project, created date, and updated date.

## 5. User Interface Aesthetics and Interaction Guidelines

1. **Zero-Emoji Policy**: Pure vector SVGs, crisp typography, and semantic badge tokens.
2. **Theme Consistency**: Seamless switching between Dark Mode (`#18181B` base, `#27272A` borders) and Light Mode (`#FFFFFF` base, `#E4E4E7` borders).
3. **Visual Balance**: Maintain minimal horizontal footprint in bottom bar so all controls fit gracefully on compact displays without horizontal scrolling.
